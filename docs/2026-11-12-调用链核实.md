## 身份与工具

- 在根会话选择 acp 模型后，外部 CLI 负责该轮回答。插件 spawn 独立进程，经 initialize / session/new 创建独立 ACP 会话；不是复用 Codex/Qoder/WorkBuddy 桌面版当前主聊天，也不是调用本 Codex 聊天的子 agent。
- released 明确拦截 origin=subagent、purpose 请求及 sessionId 不匹配。driver 注册的是根轮 driver，默认桌面安装使用 released。
- released 每轮创建/关闭连接；driver 复用会话、发送增量上下文。历史投影不包含 DSH system/developer 消息，不能视为完整继承 DSH 主 agent 配置。
- 工具不完全互通：released 不桥接；driver 通过 HTTP MCP 单向提供配置内的 read、skill，仍走 DSH 工具执行器及审批；外部 CLI 自带工具不会反向注册到 DSH。CLI 内部委派给其他 agent 的工具传播需要供应商自身支持，插件没有实现这层递归桥接。
- WorkBuddy 还返回扩展 mainAgentSupport=false / delegateToolsSupport=true；这些是厂商扩展，不能据名称推断正在复用桌面主 agent。

## 逐项审批

此前：原生 ACP 请求全部拒绝。现在：每次 session/request_permission 调用 owning agent 的 ctx.approval.request；只接受 allowed-once，并映射 ACP allow_once，不使用 allow_always。未找到一次允许选项也不授予长期允许。拒绝、取消、异常及服务缺失均关闭许可。

本机依据：dsh-user-approval/lib/index.js 的 request / decide，dsh-client-ui-approval/lib/client.js 的 answerApproval 支持无 callId 的独立请求与 reason 展示。外部调用的标题、kind、locations、rawInput 放入审批说明（最多 16 KiB）；这不是 DSH 工具的权限规则或沙箱迁移。CLI 自行执行但未发 ACP 审批的行为，DSH 无法拦截。CLI 若配置自动放行，也可能没有上报机会。

driver 已有的 MCP 中间许可只负责让调用到达网关；真正的 DSH 工具执行仍会进入 tools/pre-execute，并把 allow 升为 ask；不能把这层中间许可当成最终授权。

## 运行截止

移除两模式 prompt 的 AbortSignal.timeout；旧 promptMs 配置不再生效。startupMs 默认 0，探测脚本也默认不限时。可显式设置正数 startupMs 来排查挂起启动。保留用户停止、卸载、取消宽限、已结束轮次的 idle 回收、字节限额与 CLI 自身退出处理。

尚不能保证宿主/厂商不存在其他截止。回归使用极短旧 promptMs 和延迟响应验证不会截断；尚未完成真实桌面超过 10 分钟任务验收。

## 图片

此前存在三层缺口：模型目录写死 text，projectContext 拒绝非文字，session/prompt 只发 text。

现在：读取 DSH 当前及未覆盖历史的 durable image ref，调用 attachments.readImage 验证存储内容，作为 ACP base64 image 块发送；JSON 文字里保留图片编号与消息 seq 关联。独立 maxImageBytes 默认 20 MiB；文字上限不计图片 base64。读取缺失/损坏或字节超限直接报错。通用 file 附件仍拒绝。

模型目录按 initialize.agentCapabilities.promptCapabilities.image 声明输入；实际 prompt 再核对能力。ACP 这里是 agent 级能力，不是每个模型的视觉保证。发现失败时保守退为 text，需要先修复登录/路径再刷新目录（缓存 30 秒）。
