# DSH ACP Agent Hub 安装说明

适用于 Windows 官方 DeepSeek Harness Desktop **0.2.2-rc.1**，插件版本 **0.4.0**。把本说明和 `dsh-acp-agent-hub-0.4.0.tgz` 一起发给使用者。每位使用者在自己的电脑上准备并登录要用的智能体，可以只用其中一个。

## 准备智能体

- **Codex** 需要 Node.js 和已登录的 Codex。先在 PowerShell 运行 `node --version`，确认能启动 Node（已用 24.x 验证）。推荐安装官方 CLI：`npm.cmd install -g @openai/codex`，再运行 `codex login`。插件内含 ACP 适配器，会优先选用带 `codex-code-mode-host.exe` 的完整安装（全局 CLI → Codex Desktop 的版本目录），也支持从 `PATH` 使用 `codex` 命令。Codex 的 Code Mode 靠与 `codex.exe` 同目录的 `codex-code-mode-host.exe` 启动：只复制了 `codex.exe` 的目录（例如 `%USERPROFILE%\.codex\.sandbox-bin\` 这类沙箱副本）能回文字，但一调用命令工具就会报 `code-mode host executable not found`。[Codex ACP 文档](https://github.com/agentclientprotocol/codex-acp#installation)
- **Qoder** 使用 Qoder CLI 的登录态。若 CLI 位于 Windows 默认安装目录，可用 PowerShell 登录。[Qoder CLI ACP 文档](https://docs.qoder.com/cli/acp)

```powershell
& "$env:USERPROFILE\.qoder\bin\qodercli\qodercli.exe" login
```

- **WorkBuddy** 使用 WorkBuddy 桌面版随附的 CLI（默认 `C:\Program Files\WorkBuddy\resources\app.asar.unpacked\cli\bin\codebuddy`），插件会自动探测（含注册表里记录的非系统盘安装路径），也可用 `DSH_ACP_WORKBUDDY` 指定。桌面版只带精简 bundle，插件会自动改用 `--serve --acp --acp-transport stdio --port 0` 并注入 `CODEBUDDY_FORCE_LITE_WB_BUNDLE=1`，因此每条连接还会在 `127.0.0.1` 的随机端口短暂启动一个带密码的本地 HTTP 服务。

  WorkBuddy CLI 的登录态只在单次进程内有效。插件会在握手后自动调用 ACP `authenticate`（默认 `internal`，即微信登录）再建会话，通常不需要手动登录；需要改用其他登录方式时设置 `DSH_ACP_WORKBUDDY_AUTH`（`internal`、`external`、`iOA`、`selfhosted`）。

## 安装和使用

1. 保留下载的 `.tgz` 文件。在 DSH 桌面版打开「插件」→「添加插件」。若升级已有版本，先在插件页卸载旧版。
2. 在「包名或地址」粘贴 `.tgz` 文件的完整路径，点「安装」。安装时 DSH 会从 npm 获取依赖。安装成功后点「立即启用」，并按界面提示重启。
3. 打开工作区和会话，在输入区右下角打开模型菜单，选择 Codex、Qoder 或 WorkBuddy 下的具体模型。
4. 回复过程中，智能体的思考过程会以「思考」块出现，可以展开查看；不需要的话在插件配置里设 `showThoughts: false`。

## 只显示 Default model

这表示 DSH 尚未从该智能体读到模型目录。先确认安装的版本是 **0.4.0**，并检查 Node 和对应的 CLI 登录。如果使用了自定义安装位置，可在 Windows 用户环境变量里指定完整路径，然后从系统托盘退出 DSH 再重新打开。

| 变量 | 用途 |
| --- | --- |
| `DSH_ACP_NODE` | 自定义 `node.exe` 完整路径 |
| `DSH_ACP_CODEX_ENTRY` | 自定义 Codex ACP 的 `dist/index.js` 完整路径。默认使用随插件安装的适配器 |
| `CODEX_PATH` | 指定要使用的 `codex.exe` 完整路径，优先于自动检测。目录里缺少 `codex-code-mode-host.exe` 时插件会改用完整安装并记录一条说明 |
| `DSH_ACP_QODER` | 自定义 `qodercli.exe` 完整路径 |
| `DSH_ACP_WORKBUDDY` | 指定 WorkBuddy `codebuddy` 启动脚本或可执行文件，优先于自动检测 |
| `DSH_ACP_WORKBUDDY_AUTH` | WorkBuddy 的 ACP 登录方式，默认 `internal`（微信登录） |
| `CODEBUDDY_AUTH_TOKEN` / `CODEBUDDY_API_KEY` | 透传给 WorkBuddy CLI 的凭据 |

如果之前在 DSH 配置中手动覆盖过 `acp-agent-hub` 的启动参数，该覆盖会继续生效。要使用新包的自动检测，可移除这条自定义配置后重启 DSH。

## 这一版的能力边界

支持文字对话、流式回复、思考过程展示、模型切换和同一 DSH 会话内续聊。每轮用 DSH 可见文本历史创建提示；连接和 ACP 会话在空闲一段时间后回收。`released` 接入方式下，DSH 的工具、技能不桥接给外部 CLI，外部 CLI 使用自己的权限配置，插件拒绝经 ACP 发起的原生工具审批。附件（图片/文件）暂未接入。需要工具桥接时改用 `driver` 接入方式，并要求智能体支持 HTTP MCP。


## 0.5.0 升级与验收（2026-11-12）

新包修复运行截止、原生审批统一拒绝及图片未传递。卸载旧包后安装 `dist/dsh-acp-agent-hub-0.5.0.tgz`，启用并重启。已有配置如保留正数 startupMs，改为 0 才能关闭启动截止；旧 promptMs 已忽略。

在真实账号下分别验收：工具一次允许/拒绝/取消、图片问答、超过 10 分钟的任务和手动停止。默认 released 不桥接 DSH 工具。

本机安装解析器支持 `github:zzhiyoung/DSH-plugin`、`https://github.com/zzhiyoung/DSH-plugin.git`、`git+https://github.com/zzhiyoung/DSH-plugin.git`、以 `.tgz` / `.tar.gz` 结尾的 HTTP URL 与 npm 包名；仍待真实网络安装。私库需 Git 认证。仓库未发布 npm 包时不能直接填包名安装。内置版本升级针对 registry，GitHub push 不自动更新本地包。


## 0.6.0：DSH 工具与插件审批设置

新包为 `dist/dsh-acp-agent-hub-0.6.0.tgz`。卸载旧包、安装新包并重启后，插件的可热更新设置应由 DSH 自动生成；默认使用 DSH 工具并按 DSH 权限规则执行。已有安装的原 patch 配置未必自动替换，可参考下列设置或在表单选择：

```yaml
toolSource: dsh
toolApproval: rules
nativeApproval: dsh
tools: []
permissionMode: ''
```

不要为使用 MCP 切换到实验 driver；当前桌面版使用 released 即可。外部 CLI 需要 HTTP MCP。工具来源为 external 可关闭桥接。

按 [工具与审批配置](工具与审批配置.md) 验证设置保存、DSH MCP/技能调用、允许/询问/拒绝及手动停止。界面验收尚未完成。
