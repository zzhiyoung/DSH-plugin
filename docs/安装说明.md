# 安装说明（0.8.5）

适用于 Windows 官方 DeepSeek Harness Desktop。插件启动时检查必要的宿主能力。当前插件版本以 `package.json` 的 **0.8.5** 为准。

## 准备 CLI

- **Node.js**：本项目使用 Node 24 验证；DSH 需要能启动 `node.exe`，自定义位置可设 `DSH_ACP_NODE`。
- **Codex**：准备已登录的 Codex CLI 或完整 Codex Desktop 安装。插件内含 ACP 适配器；`codex.exe` 旁必须有 `codex-code-mode-host.exe` 才能执行 Code Mode 命令。可用 `CODEX_PATH` 指定完整安装。
- **Qoder**：支持 npm 的 `@qoder-ai/qodercli` 和旧版原生 CLI。插件自动查找 npm 前缀、`%APPDATA%\npm`、PATH 和旧路径，用 Node 启动 npm 的 JS 入口。需要时运行 `qodercli login`；桌面版已登录不证明 CLI 已登录。
- **WorkBuddy / CodeBuddy**：可使用桌面自带 CLI 或官方完整 CLI。默认自动查找桌面安装路径和卸载注册表；完整 CLI 需用 `DSH_ACP_WORKBUDDY` 指向其 `bin/codebuddy`。两种已识别布局均使用 `--serve --acp --acp-transport stdio --port 0`，避免固定端口与桌面冲突。

## 安装或升级插件

1. 在仓库运行 `npm run check`、`npm test` 和 `npm pack`，得到 `dsh-acp-agent-hub-0.8.5.tgz`。
2. DSH 打开“插件 → 添加插件”，填写源码目录或 `.tgz` 的完整路径。升级本地包时，使用插件页卸载旧包、安装新包的流程。安装可能需要从 npm 获取依赖。
3. 安装后启用插件，从托盘完全退出 DSH 再启动。用户环境变量只对新进程生效。
4. 在插件页核对安装版本为 **0.8.5**，并检查原有的 `cordis.patch.yml` 覆盖项。默认 `execution: released`、`toolSource: dsh`、`toolApproval: rules`、`nativeApproval: dsh`、`startupMs: 60000` 和 `maxContextBytes: 131072`。
5. 打开会话，在输入框旁点击 **ACP 连接**，查看状态；登录恢复步骤见下一节。模型可从右下角模型菜单选择。

GitHub 安装源解析器已核对支持 `github:zzhiyoung/DSH-plugin`、仓库 `.git` HTTPS 地址、Git URL、HTTP `.tgz` / `.tar.gz` 和 npm 包名；这不代表每一种真实网络安装都已验收。仓库未发布 npm 包时，不能只填包名安装。DSH 内置升级针对 registry 来源，GitHub push 不会自动升级本地源码或 tgz 安装。

本机 2026-11-15 常规升级曾因旧依赖树中的 `encodeurl@2.0.3` 无法解析而失败；这属于依赖安装故障，不能解释成 CLI 未登录。应保留原配置和诊断记录，核对依赖源与锁文件后处理，避免先卸载唯一可用安装。

## 连接检测和登录

0.8.3 在输入框旁提供常驻 **ACP 连接** 入口。新会话未选择模型时也可用。原模型菜单根层的检测面板保留，但 DSH 未选模型时直接打开模型列表子菜单，该子菜单不渲染旧面板。

- 启动或启用插件时，默认后台连接各智能体一次，只握手和创建会话，不主动登录，也不发送模型请求。
- 点对应智能体的“刷新”后，会发送一条只要求回复 OK 的验证消息，可能产生模型用量。只有明确的 AUTH 错误才尝试一次登录；请在浏览器完成认证，随后插件在同一进程复验。
- 显示“目录已连接”仅代表握手和会话创建成功；“对话已验证”说明最近一次模型请求成功，不保证同组所有模型可用。
- AUTH 失败显示“需要登录”；其他探测失败显示“检测失败”。登录失败、取消或超时不会自动循环登录，可再次手动刷新。
- 同一智能体的刷新和对话串行，重复刷新合并；不同智能体独立。普通对话不会自动打开登录。

若前端入口无法使用，可在会话执行 `/acp-refresh acp-workbuddy`；其他提供方 ID 为 `acp-codex`、`acp-qoder`。这与按钮执行相同的验证和登录流程。

## WorkBuddy 官方完整 CLI

1. 安装 `npm.cmd install -g @tencent-ai/codebuddy-code`，用 `codebuddy --version` 确认。当前适配依据包括本机完整 CLI 2.184.0。
2. 设置用户环境变量 `DSH_ACP_WORKBUDDY`，值为该 npm 包的 `bin/codebuddy` 完整路径。保留 WorkBuddy 行的空 `args`，让插件补全参数。
3. 安装插件后完全退出并重开 DSH，再点 **ACP 连接 → WorkBuddy → 刷新** 完成登录。也可先在终端运行 `codebuddy` 后执行 `/login`。
4. 默认登录方法为 `internal`；如账号使用其他入口，可设 `agents[].auth` 或 `DSH_ACP_WORKBUDDY_AUTH` 为 `iOA`、`external`、`internal`、`selfhosted` 中实际支持的一种。

完整 CLI 默认保留自己的文件凭据，不注入内存模式，但**不保证重启免登或桌面共存**。本机完整 CLI 与桌面仍共用 `~/AppData/Local/CodeBuddyExtension/Data/Public/auth/`；authenticate 可能先 logout 再 login。`CODEBUDDY_CONFIG_DIR` 不能单独保证这部分共享凭据已隔离。

精简桌面布局默认注入 `CODEBUDDY_CREDENTIALS_IN_MEMORY=1`，避免独立进程缺少桌面加密引导时回读凭据失败。完整版如仍出现共享凭据冲突，也可在 WorkBuddy 行显式配置：

```yaml
env:
  - CODEBUDDY_CREDENTIALS_IN_MEMORY=1
```

内存模式只保留当前进程的登录，退出 DSH 后需再次登录。用户写入自定义 `args` 会跳过 WorkBuddy 自动参数和环境变量注入，此时需自行配齐；不要为恢复登录反复触发 authenticate。

## 排查路径和等待

| 配置或变量 | 当前行为 |
| --- | --- |
| `DSH_ACP_NODE` | Node 可执行文件路径 |
| `CODEX_PATH` | Codex 路径；缺少相邻 Code Mode helper 时尝试回退完整安装 |
| `DSH_ACP_CODEX_ENTRY` | 自定义 Codex ACP JS 入口；默认使用内置版本 |
| `DSH_ACP_QODER` | Qoder `.exe`、npm `.cmd` 或 JS 入口 |
| `DSH_ACP_WORKBUDDY` | WorkBuddy / CodeBuddy 启动脚本或可执行文件 |
| `discoveryMs: 60000` | 握手、建会话、手动验证各阶段的等待预算；旧配置 15000 不会自动被替换 |
| `discoveryWaitMs: 800` | 模型菜单首次等待预算；超出先返回默认入口或已有模型 |
| `loginMs: 180000` | 手动登录的独立等待上限 |
| `startupMs: 60000` | 普通对话获准使用该连接后，握手、建会话和配置共享的预算。`0` 取消启动截止。旧 `promptMs` 已忽略 |
| `maxContextBytes: 131072` | 保留完整本轮输入与预算内的最近历史。旧 `0.8.4-local.1` 用户可显式设为 `0` 以保留不限文字字节数的行为 |

成功目录缓存 5 分钟，失败冷却 30 秒；手动刷新可绕过冷却。默认入口不证明已登录。路径错误、AUTH、超时、额度和限流应分别排查。

## 当前能力与验收边界

默认 `released` 模式可以桥接 DSH 工具、已注册 MCP、技能和 PTC/run_code。当前有可桥接工具时，外部智能体必须声明 HTTP MCP 能力。工具来源、审批和白名单见[工具与审批配置](工具与审批配置.md)。

支持文字、思考过程和 ACP 声明支持的图片输入；通用文件附件尚未接入。默认 released 按提供方保留一个 CLI 进程，每轮创建独立 ACP 会话；实验 driver 使用按 DSH 会话绑定的生命周期。插件停止、CLI 故障、取消等清理仍有效；运行不设总截止不代表上下游没有限制。

自动测试、真实协议检查和桌面账号验收分别记录。长期桌面/CLI 共存、重启后免登、所有模型、真实工具与图片链路仍需逐项验证。历史版本变化见 [CHANGELOG](../CHANGELOG.md)，后续事项见[开发清单](后续核实与开发清单.md)。
