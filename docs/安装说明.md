# DSH ACP Agent Hub 安装说明

适用于 Windows 官方 DeepSeek Harness Desktop，插件版本 **0.8.3**；已核对 **0.2.2-rc.3** 宿主接口。版本不再锁定，必要接口缺失时由启动自检报错。把本说明和 `dsh-acp-agent-hub-0.8.3.tgz` 一起发给使用者。每位使用者在自己的电脑上准备并登录要用的智能体，可以只用其中一个。

## 准备智能体

- **Codex** 需要 Node.js 和已登录的 Codex。先在 PowerShell 运行 `node --version`，确认能启动 Node（已用 24.x 验证）。推荐安装官方 CLI：`npm.cmd install -g @openai/codex`，再运行 `codex login`。插件内含 ACP 适配器，会优先选用带 `codex-code-mode-host.exe` 的完整安装（全局 CLI → Codex Desktop 的版本目录），也支持从 `PATH` 使用 `codex` 命令。Codex 的 Code Mode 靠与 `codex.exe` 同目录的 `codex-code-mode-host.exe` 启动：只复制了 `codex.exe` 的目录（例如 `%USERPROFILE%\.codex\.sandbox-bin\` 这类沙箱副本）能回文字，但一调用命令工具就会报 `code-mode host executable not found`。[Codex ACP 文档](https://github.com/agentclientprotocol/codex-acp#installation)
- **Qoder** 使用 Qoder CLI 自己的登录态。0.7.1 支持 npm 安装并自动查找入口；npm 默认前缀可用以下 PowerShell 命令登录。[Qoder CLI ACP 文档](https://docs.qoder.com/cli/acp)

```powershell
& "$env:APPDATA\npm\qodercli.cmd" login
```

- **WorkBuddy** 使用 WorkBuddy 桌面版随附的 CLI（默认 `C:\Program Files\WorkBuddy\resources\app.asar.unpacked\cli\bin\codebuddy`），插件会自动探测（含注册表里记录的非系统盘安装路径），也可用 `DSH_ACP_WORKBUDDY` 指定。桌面版只带精简 bundle，插件会自动改用 `--serve --acp --acp-transport stdio --port 0` 并注入 `CODEBUDDY_FORCE_LITE_WB_BUNDLE=1`，因此每条连接还会在 `127.0.0.1` 的随机端口短暂启动一个带密码的本地 HTTP 服务。官方完整版 CLI 同样走 `--serve ... --port 0`，但不会注入 bundle 或内存凭据变量，详见文末 0.8.2 段落。

  0.6.2 默认 authMode: existing，仅尝试已有 CLI 凭据；后台探测不主动登录。此前无条件 authenticate 会调用 CLI 的强制退出再登录逻辑，可能反复弹浏览器并影响桌面登录，不能据此断言登录态只在单进程有效。免登不可用时会明确失败；只有显式 authMode: authenticate 才执行重新认证。

## 安装和使用

1. 保留下载的 `.tgz` 文件。在 DSH 桌面版打开「插件」→「添加插件」。若升级已有版本，先在插件页卸载旧版。
2. 在「包名或地址」粘贴 `.tgz` 文件的完整路径，点「安装」。安装时 DSH 会从 npm 获取依赖。安装成功后点「立即启用」，并按界面提示重启。
3. 打开工作区和会话，在输入区右下角打开模型菜单，选择 Codex、Qoder 或 WorkBuddy 下的具体模型。
4. 回复过程中，智能体的思考过程会以「思考」块出现，可以展开查看；不需要的话在插件配置里设 `showThoughts: false`。

## 只显示 Default model

这表示 DSH 尚未从该智能体读到模型目录。先确认安装的版本是 **0.6.2**，并检查 Node 和对应的 CLI 登录。如果使用了自定义安装位置，可在 Windows 用户环境变量里指定完整路径，然后从系统托盘退出 DSH 再重新打开。

| 变量 | 用途 |
| --- | --- |
| `DSH_ACP_NODE` | 自定义 `node.exe` 完整路径 |
| `DSH_ACP_CODEX_ENTRY` | 自定义 Codex ACP 的 `dist/index.js` 完整路径。默认使用随插件安装的适配器 |
| `CODEX_PATH` | 指定要使用的 `codex.exe` 完整路径，优先于自动检测。目录里缺少 `codex-code-mode-host.exe` 时插件会改用完整安装并记录一条说明 |
| `DSH_ACP_QODER` | 自定义 `qodercli.exe` 完整路径 |
| `DSH_ACP_WORKBUDDY` | 指定 WorkBuddy `codebuddy` 启动脚本或可执行文件，优先于自动检测 |
| `DSH_ACP_WORKBUDDY_AUTH` | WorkBuddy 的 ACP 登录方式，默认 `internal`（微信登录） |
| `CODEBUDDY_AUTH_TOKEN` / `CODEBUDDY_API_KEY` | 透传给 WorkBuddy CLI 的凭据 |

如果之前在 DSH 配置中手动覆盖过 `acp-agent-hub` 的启动参数，该覆盖会继续生效。要使用新包的自动检测，可移除这条自定义配置后重启 DSH。

## 这一版的能力边界

支持文字对话、流式回复、思考过程展示、模型切换和同一 DSH 会话内续聊。每轮用 DSH 可见文本历史创建提示；连接和 ACP 会话在空闲一段时间后回收。`released` 接入方式下，DSH 的工具、技能不桥接给外部 CLI，外部 CLI 使用自己的权限配置，插件拒绝经 ACP 发起的原生工具审批。附件（图片/文件）暂未接入。需要工具桥接时改用 `driver` 接入方式，并要求智能体支持 HTTP MCP。

## 0.6.0：DSH 工具与插件审批设置

新包为 `dist/dsh-acp-agent-hub-0.6.0.tgz`。卸载旧包、安装新包并重启后，插件的可热更新设置应由 DSH 自动生成；默认使用 DSH 工具并按 DSH 权限规则执行。已有安装的原 patch 配置未必自动替换，可参考下列设置或在表单选择：

```yaml
toolSource: dsh
toolApproval: rules
nativeApproval: dsh
tools: []
permissionMode: ''
```

不要为使用 MCP 切换到实验 driver；当前桌面版使用 released 即可。外部 CLI 需要 HTTP MCP。工具来源为 external 可关闭桥接。

按 [工具与审批配置](工具与审批配置.md) 验证设置保存、DSH MCP/技能调用、允许/询问/拒绝及手动停止。界面验收尚未完成。


## 0.6.1：模型目录部分加载（2026-11-14）

本地修复包：`dist/dsh-acp-agent-hub-0.6.1.tgz`。0.6.0 若卡在「正在刷新模型列表」，此补丁为目录发现单独设置等待预算：每个 ACP provider 首次最多等待 800 毫秒，先给默认入口或已有列表，后台探测最多 15 秒（清理另算），完成后发送模型更新事件。失败保留旧目录，冷却 30 秒后刷新重试。

配置为 discoveryMs=60000、discoveryWaitMs=800；这两个设置不限制已运行的对话任务，也不受 startupMs=0 的无限等待影响。默认入口不保证账号已登录；仍需解决 CLI 路径或登录问题。真实桌面自动补齐效果待验收，尚未通过 GitHub 发布本补丁。


## 0.6.2：WorkBuddy 默认不主动重认证（2026-11-14）

本地包 `dist/dsh-acp-agent-hub-0.6.2.tgz` 包含 0.6.1 的目录加载修复。升级后 WorkBuddy 默认 authMode: existing，即使旧配置保留 auth: internal，也不主动调用 authenticate；后台刷新模型列表不会主动认证。需在实际使用中核实 CLI 能否读取已有有效凭据。

若需要显式登录，可配置 authMode: authenticate 和 auth: internal，但本机 CLI 的此方法会先退出已有会话，仍可能影响桌面账号。此模式不是免登修复。当前没有验证两端并存的官方方案，不应复制桌面账号令牌或宣称换目录即可解决。0.6.2 尚未安装到本机 DSH，也未推送 GitHub。

## 模型检测与刷新

点击输入框旁的“ACP 连接”，查看各提供方状态并点击对应“刷新”。未选择模型的新会话也能使用；DSH 的模型列表子菜单不渲染菜单根层的刷新面板，原根层面板仍保留。转圈仅表示该提供方正在检测，其他已就绪模型仍可选择。后台发现 AUTH 错误显示“需要登录”；点击刷新才允许发起一次登录验证。

## Qoder 已安装但检测失败

0.7.1 自动识别 npm 安装，不再仅使用旧版原生 exe 路径。安装新插件并重启 DSH。若仍提示需要登录，在 PowerShell 执行 `& "$env:APPDATA\npm\qodercli.cmd" login`（npm 默认安装前缀），按浏览器提示完成 CLI 登录，再刷新 Qoder。插件不会替用户主动重新登录。

## 冷启动与 WorkBuddy 认证（0.7.2）

目录发现默认等待截止延长到 60 秒；菜单仍只等待 800 毫秒，不影响其他已加载模型。若旧配置显式设置了 discoveryMs: 15000，需要自行改为 60000 或删除该项使用新默认值。

“目录已连接”不表示模型对话已验证。WorkBuddy 返回 Authentication required 时，即使能列出模型，也需要恢复 CLI 对话认证；插件不会擅自 authenticate，因为它可能先 logout 并影响桌面登录。目录刷新成功不会清除已经发现的对话认证失败。

## 0.8.0 刷新流程

安装并重启 DSH，插件会在后台启动各 agent 连接一次。目录连接成功只表示能够创建会话。点击对应“刷新”后，还会发送一条最小验证消息；遇到明确的认证失败时发起一次登录，按浏览器提示完成，随后在同一进程再次验证。这个操作可能产生模型用量，WorkBuddy 可能先退出既有账号。失败后不会自行循环登录；可再次手动刷新。

状态包括检测中、验证登录中、等待登录、对话已验证、需要登录。其他 agent 的状态与使用独立。默认 released 会保留登录后的进程，每轮创建独立会话；关闭 DSH/卸载插件时一并清理。后台启动检查不主动登录。

## 0.8.1 WorkBuddy 凭据隔离

自动识别出的桌面精简版 CLI 使用独立内存登录，避开共享凭据文件缺少加密密钥的问题。安装后重启 DSH，点击 WorkBuddy 刷新完成一次浏览器登录。关闭 DSH 后需重新登录；模型目录更新不等于验证回复成功。客户端和 CLI 的服务端账号共存仍待实测。

## 0.8.2 官方完整版 CLI

1. 安装：`npm.cmd install -g @tencent-ai/codebuddy-code`（本机已装 2.184.0）。用 `codebuddy --version` 确认。
2. 设置用户环境变量 `DSH_ACP_WORKBUDDY` 为完整版 CLI 的 `bin/codebuddy` 完整路径，然后**从托盘完全退出 DSH 再启动**，否则新进程读不到该变量。
3. 先让 CLI 自己登录：终端运行 `codebuddy`，用 `/login` 选择 iOA / external / internal / selfhosted 完成浏览器认证；或在 DSH 模型菜单点 WorkBuddy「刷新」触发一次登录。
4. 卸载旧插件包、安装 `dist/dsh-acp-agent-hub-0.8.2.tgz` 并重启。0.8.2 对完整版也使用 `--serve --acp --acp-transport stdio --port 0`：桌面端占用 `127.0.0.1:13034` 时，普通 `--acp` 会 `EADDRINUSE`。
5. 若两端仍互相登出，可在 workbuddy 行的 `env` 加 `CODEBUDDY_CREDENTIALS_IN_MEMORY=1`，让 CLI 不读写共享 auth 文件（代价：DSH 重启后需重新登录一次）。完整版与桌面共用 `~/AppData/Local/CodeBuddyExtension/Data/Public/auth/` 下的凭据文件和 watcher，换完整版本身不消除这个耦合。
