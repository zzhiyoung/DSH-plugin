# 工具与审批配置（0.6.0）

用户确认的默认行为：按 DSH 权限规则自动处理，需要确认时再询问。

## 工具来源

- `toolSource: dsh`：优先使用 DSH 工具。复用当前作用域的 DSH 运行时、MCP 连接和 skill 加载器，通过临时 HTTP MCP 网关交给外部 agent。凭据不复制到外部 agent 配置。
- `toolSource: external`：不建立 DSH 工具桥接。
- `tools: []` 表示作用域内全部可用工具；非空则限制工具名，包括 `mcp__server__tool`。PTC 模式限制的是 run_code 内可调用的工具，不能仅靠过滤入口名字授权。
- native 执行器按工具列出；PTC 执行器保留 run_code 与工具 SDK，不绕过其执行限制。调用前和 tools/list 可刷新目录，技能触发的新能力仍受 DSH 自己的激活条件约束。
- 这是工具复用，不等于复制 MCP resources/prompts、全部 DSH 内部服务，或强制关闭外部 CLI 自带工具。ACP 没有一个通用的“禁用所有原生工具”开关。

## 两条审批链

| 设置 | 含义 | 边界 |
| --- | --- | --- |
| toolApproval=rules（默认） | 保留 DSH 的允许/询问/拒绝，必要时由其审批服务询问 | 用户已选此项；不自动放宽现有拒绝 |
| toolApproval=ask | 桥接调用额外要求询问 | 只能把 allow 收紧为 ask，不能覆盖 deny；嵌套调用同样识别 |
| nativeApproval=dsh（默认） | CLI 原生工具的 ACP 请求交 DSH 确认 | 原生工具不是 DSH ToolDefinition，不能伪称套用了 DSH 工具规则 |
| nativeApproval=agent | 采用外部 CLI 权限模式，可由 permissionMode 指定 | CLI 仍转交的请求回到 DSH 确认，不做 blanket allow |
| nativeApproval=deny | 拒绝原生工具经 ACP 发来的审批 | CLI 未上报的行为无法被此选项接管 |

permissionMode 留空沿用 CLI 当前模式；也支持每个 agents 行的 permissionMode 作为兜底。非空值必须出现在 ACP 返回的 mode 配置选项或 availableModes 中，否则失败并报告不支持。设置 configOption 时核对返回的 currentValue；旧 set_mode 按协议响应判断成功。

内置 Codex ACP 的 mode `agent` 是 Auto review（只对潜在危险操作询问），`agent-full-access` 是另一个全访问模式。不能把二者混为一谈。其他厂商未声明相同 ID 时不可套用这个值。切换 driver 的原生审批策略会回收旧绑定，避免沿用旧权限模式。

外部 CLI 本来已自动批准的行为不会触发客户端审批。若需要所有操作都受 DSH 沙箱约束，还需要逐厂商禁用或限制其原生能力；目前不作这项保证。

## 插件设置表单

toolSource / tools / toolApproval / nativeApproval / permissionMode 为 volatile 字段。本机 DSH 的 settings 服务自动收集这些字段，autoGenerate 默认为 true，故无需另装前端插件即可生成配置表单。默认条目 ID 为 acp-agent-hub。源码依据：本机 app.asar 内 dsh-settings/lib/index.js 的 volatileForm、describe；Schemastery 3.19.0 的实际 schema 已验证。

来源、白名单、原生审批策略与模式按轮次读取；额外询问策略作用于后续调用。变更不追溯已执行动作。配置持久化由 DSH 自身设置服务负责，不另写账号文件。
