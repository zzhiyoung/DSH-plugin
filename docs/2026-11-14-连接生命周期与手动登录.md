# 0.8.0 连接生命周期与手动登录

用户请求：DSH 启动时自动连接各 agent 一次；手动刷新同时检查目录和登录，未登录则发起一次登录。

## 决策

默认 released 按 provider 保留一个 CLI 进程，后台启动只 initialize/session/new，不 authenticate、不发模型任务。手动刷新会发最小 OK 请求以发现 WorkBuddy 的延迟认证失败；AUTH 才允许一次 authenticate，之后在同一进程创建新会话复验。认证等待默认 180 秒，连接和响应验证分别使用 discoveryMs。刷新返回验证结果，不把目录连接当成完整登录证明。

连接进程保留是必要的：单独登录脚本完成后退出，无法证明 WorkBuddy 会把登录态保存给下一个 CLI 进程。本设计不依赖跨进程凭据持久化。普通对话不自动认证；需要时由用户点击刷新。WorkBuddy 重新认证可能影响桌面账号，用户已明确授权手动刷新时发起一次登录。

同一 agent 串行使用进程；每次实际请求创建独立 ACP 会话，传入真实工作区和本轮临时 MCP 网关。声明支持 session/close 时先关闭旧会话，避免混入其他 DSH 会话历史。跨 provider 独立。shutdown 取消连接/验证/认证，等待任务收敛后关闭进程和临时目录。MCP 网关在租用释放前关闭，启动失败路径也会清理。

实验 driver 的原有按会话绑定机制保留；本次生产改动以默认 released 为目标。源代码与文档保留既有 WIP，未替换已安装插件或推送。

## 验证

- 常规测试：启动无菜单调用自动连接、已有登录不重认证、建会话阶段与请求阶段的 AUTH 均触发一次认证、失败不重试、重复点击合并、其他 provider 不阻塞、卸载取消等待与关闭进程。
- 真实 ACP SDK 1.4.0 + 本地假 agent 子进程：从 refusal metadata 识别 AUTH，在原进程完成认证，连续创建/关闭 ACP 会话后仍能响应。不是用户账号登录成功或真实桌面验收。
- 端到端 released 测试：手动登录后普通对话复用同一进程、创建新的工作区会话；失败启动时每轮 MCP 网关仍恰好关闭一次。

仍需用户安装后验证 WorkBuddy 浏览器登录、登录后模型响应及与桌面登录是否能共存。
