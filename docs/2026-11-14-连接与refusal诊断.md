# 连接与 refusal 诊断（2026-11-14）

范围：桌面已安装插件 0.7.1；本仓库修复为 0.7.2。保留已有 WIP，未改账号登录状态、未部署已装插件。

## 实际证据

- 读取 DSH 对应会话的压缩事件，只定位 provider/turn end：三次 refusal 的选择均为 acp-workbuddy（auto、glm-5.1、glm-5.0）；Qoder fast 曾成功处理图片。
- 正常用户环境的 ACP 空会话：Codex ACP 2.6.0 在 395 ms 完成 initialize，26562 ms 完成 session/new；Qoder CLI 1.1.89 分别 9764 ms / 26077 ms。均超过原 15000 ms 检测截止。
- Codex 只回复 OK、不使用工具的实际对话：20919 ms 建会话，34115 ms 返回 end_turn 和 OK。
- WorkBuddy glm-5.1：1471 ms 握手、1683 ms 创建会话，3157 ms 返回 refusal；正文为空，_meta[codebuddy.ai/errorMessage] 是 JSON：code=-32000，message=Authentication required，data.category=auth。目录与会话创建未验证模型服务认证。
- Qoder 的额外完整对话测试因自动审批服务 403 未执行。这是审批服务故障，非不安全判定；不绕过审批。已有空会话测试和 DSH 图片成功事件作为不同层次的证据。

## 修复

1. 默认目录截止 60 秒，成功目录缓存 5 分钟，失败冷却 30 秒；菜单首次等待 800 ms，继续按 provider 共享在途探测。
2. 解析已知的模型服务错误并分类，避免只留下 UNKNOWN/refusal；不复制原始 CLI 错误中的 URL、令牌或输出。
3. 目录状态与实际对话结果分开。仅成功发起模型请求才标对话已验证，并说明最近成功的模型选择；不承诺其他模型也已验证。
4. 真实对话连接更新目录，旧探测结果不能覆盖新连接；刷新目录不能清除已知对话认证失败。

## 边界

WorkBuddy 登录仍未恢复。主动 authenticate 可能 logout 再 login，可能影响桌面登录，因此没有执行。目录检测不发送模型请求、不重新登录，不能代替实际账号验收。升级后仍需要在 DSH 验证刷新、切换模型和正常会话；本文不把单元测试提升为桌面验收。
